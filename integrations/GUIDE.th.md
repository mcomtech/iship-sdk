# คู่มือเชื่อม iShip กับ Shopify, TikTok Shop และ Odoo

เอกสารนี้สรุปว่าโค้ดทำอะไรให้แล้ว และคุณต้องทำอะไรเองบ้าง เรียงตามลำดับที่ควรทำ

## สถานะตอนนี้

| ช่องทาง | สถานะ |
| --- | --- |
| แกนกลาง (`connect/`) | เสร็จ มีเทสต์ครบ ใช้ร่วมกันได้ทุกช่องทาง |
| Shopify (`shopify-app/`) | โค้ดเฟส 1 เสร็จ ผ่าน typecheck, lint, เทสต์ และตรวจ GraphQL กับ schema จริงของ Shopify แล้ว รอทดสอบกับร้านทดสอบจริง |
| TikTok Shop | ยังไม่เริ่ม รอยืนยันว่า API ของตลาดไทยรองรับ Seller Own Fleet |
| Odoo | ยังไม่เริ่ม ต้องเขียน Python client ของ iShip ก่อน |

### แอป Shopify ทำอะไรได้แล้ว

- รับออเดอร์ใหม่อัตโนมัติ และดึงออเดอร์เก่าที่ยังไม่จัดส่งได้
- แยกตำบล อำเภอ จังหวัด รหัสไปรษณีย์ จากที่อยู่ที่ลูกค้าพิมพ์ แม้พิมพ์ติดกัน
- ที่อยู่ที่อ่านไม่ออกจะไปอยู่ในหมวด "ต้องตรวจสอบ" ให้ร้านแก้ ไม่ส่งของผิดที่
- โหมดกดสร้างเอง (ค่าเริ่มต้น) หรือโหมดอัตโนมัติ เพราะการสร้างพัสดุตัดเครดิต
- รองรับเก็บเงินปลายทาง ส่งรายการสินค้าครบตามที่ iShip บังคับ
- กันพัสดุซ้ำ ถ้าเน็ตหลุดระหว่างสร้าง ระบบจะหาพัสดุเดิมให้แทนการสร้างใหม่
- ใส่เลขพัสดุกลับไปที่ Shopify และส่งอีเมลแจ้งลูกค้า
- อัปเดตสถานะพัสดุกลับไปที่ Shopify ทุกไม่กี่ชั่วโมง หรือทันทีเมื่อ iShip ยิง webhook มา
- พิมพ์ใบปะหน้า ยกเลิกพัสดุ และส่งใหม่ได้จากในแอป
- หน้าจอภาษาไทยและอังกฤษ สลับตามภาษาของ Shopify admin
- webhook ภาคบังคับด้าน privacy ครบ 3 ตัว และเก็บ token ของ iShip แบบเข้ารหัส

## สิ่งที่คุณต้องทำเอง: Shopify

### ขั้นที่ 1: บัญชีและร้านทดสอบ

1. สมัคร Shopify Partners ให้เสร็จ (เริ่มแล้ว) ใช้ชื่อธุรกิจ `ISHIP SERVICE CO., LTD.` ให้ตรงกับหนังสือรับรอง
2. เปิด 2-step authentication ของบัญชีที่ใช้ล็อกอิน
3. ใน Partner Dashboard กด **Stores → Add store → Development store** สร้างร้านทดสอบหนึ่งร้าน
4. ในร้านทดสอบ เปิดช่องทางชำระเงิน **Cash on Delivery (COD)** ที่ Settings → Payments → Manual payment methods

### ขั้นที่ 2: รันแอปบนเครื่องนักพัฒนา

ให้นักพัฒนาทำตาม `shopify-app/README.md` สรุปคือ

1. ติดตั้ง Node 22.12 ขึ้นไป
2. รัน `npm run config:link` แล้วเลือก **Create a new app** ตั้งชื่อ `iShip`
3. สร้างไฟล์ `.env` ที่มี `ISHIP_ENCRYPTION_KEY` ตามคำสั่งใน README และเก็บค่านี้ไว้ให้ดี ถ้าหายร้านค้าทุกร้านต้องใส่ token ใหม่
4. รัน `npm run dev` แล้วกดติดตั้งแอปบนร้านทดสอบ

### ขั้นที่ 3: ทดสอบกับบัญชี UAT ของ iShip

1. เปิดหน้า **ตั้งค่า** ในแอป วาง token ของบัญชี UAT เลือกระบบ **ทดสอบ (UAT)**
2. กรอกที่อยู่ผู้ส่งให้ครบ แล้วกดบันทึก ต้องเห็นข้อความ "เชื่อมต่อแล้ว เครดิตคงเหลือ"
3. สั่งซื้อในร้านทดสอบอย่างน้อย 4 แบบ แล้วดูผลในหน้ารายการจัดส่ง
   - จ่ายแล้ว ที่อยู่พิมพ์ครบ `ต. อ. จ.` ควรขึ้น "พร้อมส่ง"
   - เก็บเงินปลายทาง ควรขึ้น "พร้อมส่ง" ทันทีโดยไม่ต้องรอจ่าย
   - ที่อยู่ไม่มีตำบล ควรขึ้น "ต้องตรวจสอบ" และแก้ได้ในหน้าออเดอร์
   - ยกเลิกออเดอร์หลังสร้างพัสดุ ควรขึ้นป้ายเตือนให้ยกเลิกพัสดุ
4. กดสร้างพัสดุ ตรวจว่าเลขพัสดุไปขึ้นในออเดอร์ของ Shopify และพิมพ์ใบปะหน้าได้
5. กดทุกปุ่มและทุกฟอร์มอย่างน้อยหนึ่งครั้ง เพราะหน้าจอผ่านแค่การตรวจโค้ด ยังไม่เคยถูกเปิดในเบราว์เซอร์จริง

### ขั้นที่ 4: ข้อมูลที่ต้องขอจากทีม iShip

1. **ตั้ง webhook สถานะพัสดุ** ได้ที่ไหน แอปมีลิงก์ให้ในหน้าตั้งค่าแล้ว ถ้าตั้งไม่ได้ แอปยังเช็กสถานะเองทุก 3 ชั่วโมง
2. **ลิงก์หน้าติดตามพัสดุสาธารณะ** ของ iShip ใส่ในช่อง "ลิงก์หน้าติดตามพัสดุ" ในรูปแบบ `https://.../{tracking}` ถ้าไม่มี ลูกค้าจะเห็นแค่เลขพัสดุ
3. **รหัส error** ของกรณีเครดิตไม่พอและ `custom_order_id` ซ้ำ เพื่อแสดงข้อความที่ชัดขึ้น
4. **บัญชี UAT สำหรับทีมรีวิวของ Shopify** ที่มีเครดิตทดสอบ และใช้ได้ตลอดช่วงรีวิว

### ขั้นที่ 5: เตรียมเซิร์ฟเวอร์จริง

1. เลือก host ที่รัน Node ค้างไว้ตลอดได้ เช่น VPS, Fly.io, Render, Railway ห้ามใช้แบบ serverless เพราะงานสร้างพัสดุรันอยู่เบื้องหลัง
2. ต้องมี disk ถาวรสำหรับฐานข้อมูล SQLite หรือเปลี่ยนเป็น PostgreSQL ถ้าจะรันหลายเครื่อง
3. ตั้งค่า environment ตามตารางใน `shopify-app/README.md` แล้วรัน `npm run deploy` เพื่อส่งการตั้งค่าแอปขึ้น Shopify
4. ใช้โดเมนของบริษัท เช่น `shopify.iship.cloud` ไม่ใช่โดเมนชั่วคราว

### ขั้นที่ 6: ขอสิทธิ์ข้อมูลลูกค้า (ต้องทำก่อนส่งรีวิว)

ใน Partner Dashboard → แอป iShip → **API access → Protected customer data access**

1. เลือก Protected customer data แล้วติ๊กเฉพาะ **Name, Address, Phone** ไม่ต้องขอ Email
2. เหตุผลที่ใช้ได้: "Name, address and phone are printed on the shipping label and sent to the courier through iShip to deliver the order."
3. ยืนยันข้อกำหนดด้านความปลอดภัย แอปทำบางข้อให้แล้ว คือเข้ารหัส token, เก็บข้อมูลลูกค้าน้อยที่สุด และลบข้อมูลตาม webhook redact ข้อที่บริษัทต้องทำเองคือ เข้ารหัส backup, แยกฐานข้อมูลทดสอบกับของจริง, จำกัดคนเข้าถึงเซิร์ฟเวอร์ และมีขั้นตอนรับมือข้อมูลรั่ว

### ขั้นที่ 7: เอกสารและหน้า listing

1. **Privacy policy** เป็นหน้าเว็บสาธารณะ ระบุว่าส่งชื่อ ที่อยู่ เบอร์โทรของผู้รับไปที่ iShip และบริษัทขนส่ง เก็บไว้นานเท่าไร และลบอย่างไร ครอบคลุม PDPA
2. **อีเมลและหน้า support** พร้อมเวลาตอบกลับ
3. **ราคา** เลือกว่าฟรี หรือคิดรายเดือน ถ้าเก็บเงินต้องให้นักพัฒนาเพิ่ม Shopify Billing API ก่อน ตอนนี้แอปยังไม่มีระบบเก็บเงิน
4. **รูปภาพ** ไอคอน 1200×1200 px, screenshot หน้าจอแอปจริง 1600×900 px 3 ถึง 6 ภาพ ภาพละหน้าไม่ซ้ำกัน
5. **คำอธิบายภาษาอังกฤษ** บังคับ เพิ่มภาษาไทยได้
6. **วิดีโอ screencast** ตั้งแต่ติดตั้ง ใส่ token สร้างพัสดุ จนเลขพัสดุขึ้นในออเดอร์ พร้อมบรรยายภาษาอังกฤษ

### ขั้นที่ 8: ส่งรีวิว

1. ใน Partner Dashboard → **Distribution** เลือก **Public distribution**
2. หน้า review กดรัน automated checks แก้จนผ่านทุกข้อ
3. ใส่ token UAT และวิธีทดสอบเป็นภาษาอังกฤษให้ทีมรีวิว แล้วกด **Submit for review**
4. ตอบ feedback ของทีมรีวิว รอบแรกมักโดนตีกลับอย่างน้อยหนึ่งครั้ง

## TikTok Shop

ทำได้ทันทีโดยไม่ต้องรอโค้ด

1. สมัคร **TikTok Shop Partner Center** ในนามบริษัท ประเภท App developer
2. ถาม account manager หรือดูเอกสาร API ตลาดไทยว่า **มี API ให้แอปส่งเลขพัสดุของขนส่งที่ร้านเลือกเอง (Seller Own Fleet) หรือไม่** เอกสารที่ค้นเจอบอกว่าเปิดแค่บางประเทศ ยังไม่เห็นไทย
3. หาร้านทดสอบที่ TikTok อนุมัติ Seller Own Fleet แล้วอย่างน้อยหนึ่งร้าน

ถ้า API ตลาดไทยพร้อม ตัวเชื่อม TikTok จะใช้แกนกลางชุดเดียวกับ Shopify ได้เลย ทั้งการแปลงที่อยู่ การกันพัสดุซ้ำ (เลขขึ้นต้น `TTS-`) และการ map สถานะ เหลือเขียนเฉพาะส่วนที่คุยกับ TikTok

## Odoo

1. เลือกเวอร์ชัน Odoo ที่จะรองรับ เช่น 17, 18, 19
2. สมัครบัญชี Odoo Apps Store และผูกกับ GitHub repository ของบริษัท
3. หาลูกค้าหรือ partner ที่ใช้ Odoo อยู่แล้วหนึ่งรายเพื่อทดสอบ

งานโค้ดคือเขียน Python client ของ iShip ให้ครบเหมือน SDK ภาษาอื่นใน repo นี้ แล้วเขียนโมดูล `delivery.carrier` ของ Odoo ครอบอีกชั้น
